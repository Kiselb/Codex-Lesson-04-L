# Описание SQL-базы проекта «Шальные Шнурки»

Приложение использует реляционную базу SQLite/libSQL. Локально файл создаётся по адресу `data/laces.sqlite`; на Vercel та же схема размещается в облачной базе Turso. Схема создаётся автоматически из файла `database/schema.sql`. Для локального режима включён `PRAGMA foreign_keys = ON`.

## Таблица `users` — пользователи и роли

| Поле | Тип | Назначение |
|---|---|---|
| `id` | TEXT, PRIMARY KEY | Уникальный UUID пользователя |
| `username` | TEXT, UNIQUE | Логин без учёта регистра |
| `password_hash` | TEXT | Хеш пароля `scrypt` с индивидуальной солью |
| `role` | TEXT | Роль `client` или `admin`, контролируется `CHECK` |
| `created_at` | TEXT | Дата создания |
| `updated_at` | TEXT | Дата последнего изменения |

## Таблица `user_facts` — долгосрочная память

Каждый факт хранится отдельной строкой. Это позволяет просматривать, изменять и удалять сведения независимо друг от друга.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER, PRIMARY KEY | Идентификатор факта |
| `user_id` | TEXT, FOREIGN KEY | Владелец факта, ссылка на `users.id` |
| `fact_key` | TEXT | Тип факта: имя, бюджет, обувь, стиль, цвет и т. п. |
| `fact_value` | TEXT | Сохранённое значение |
| `created_at` | TEXT | Дата создания |
| `updated_at` | TEXT | Дата изменения |

Ограничение `UNIQUE (user_id, fact_key)` не допускает дублирования одного типа факта у пользователя. При удалении пользователя его факты удаляются автоматически благодаря `ON DELETE CASCADE`.

## Таблица `dialogs` — диалоги

| Поле | Тип | Назначение |
|---|---|---|
| `id` | TEXT, PRIMARY KEY | UUID диалога |
| `user_id` | TEXT, FOREIGN KEY | Владелец диалога, ссылка на `users.id` |
| `created_at` | TEXT | Время начала диалога |
| `updated_at` | TEXT | Время последнего сообщения |

Каждый вход в приложение и команда «начать новый диалог» создают новую запись. Пользователь может работать только со своими диалогами.

## Таблица `messages` — история сообщений

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER, PRIMARY KEY | Последовательный идентификатор сообщения |
| `dialog_id` | TEXT, FOREIGN KEY | Ссылка на `dialogs.id` |
| `role` | TEXT | Автор: `user` или `assistant` |
| `content` | TEXT | Текст сообщения |
| `created_at` | TEXT | Время создания |

Сообщения удаляются автоматически при удалении соответствующего диалога.

## Связи

```text
users 1 ─── N user_facts
users 1 ─── N dialogs
dialogs 1 ─── N messages
```

## Память агента

- Краткосрочная память формируется из последних 20 сообщений текущего диалога.
- Долгосрочная память загружается из `user_facts` при каждом ответе, поэтому изменение строки базы сразу влияет на персонализацию.
- Пустое значение удаляет отдельный факт. API также поддерживает удаление одного факта и полную очистку памяти.

## Разграничение доступа

- Клиентские маршруты определяют пользователя только по серверной сессии. Передать чужой `user_id` в них невозможно.
- На Vercel авторизация не хранится в памяти процесса: используется подписанный токен с ограниченным сроком действия.
- Административные маршруты `/api/admin/*` перед любой операцией проверяют роль `admin`.
- Пароли не хранятся в открытом виде.
